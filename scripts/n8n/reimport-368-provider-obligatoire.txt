# `provider` et `model` sont désormais EXIGÉS par /api/translations/save-batch.
# Le lot part en UNE requête : un seul item sans provenance fait répondre 422, et
# c'est TOUT le lot qui est refusé — traductions déjà payées comprises.
#
#   1. `Torah Batch Callback` → `Grouper Sauvegardes` posait `provider`
#      CONDITIONNELLEMENT (« omis plutôt qu'inventé »), ce qui était juste tant que
#      l'API le traitait en optionnel. Il est désormais TOUJOURS posé, avec le repli
#      `'anthropic'`. Ce repli ne devine rien : le lot n'existe que chez Anthropic,
#      le dispatcher refusant explicitement tout autre fournisseur.
#   2. `Torah Batch Dispatcher` → `Build Requests` dérivait `provider` du NOM du
#      modèle quand l'appelant se tait (`/^claude/i`), et retombait sur `null`. Un
#      nom préfixé ou aliasé (`anthropic/claude-sonnet-4-6`, `sonnet-4-6`) n'y
#      correspond pas. Le dernier recours est maintenant `'anthropic'`.
#
# ⚠️ `model` reste CONDITIONNEL, et c'est délibéré. Il est exigé par le dispatcher
#    depuis la création du fichier (vérifié en historique git), donc jamais nul.
#    Lui donner un repli écrirait une provenance INVENTÉE en base — exactement ce
#    que #443 cherchait à empêcher. S'il manquait vraiment, le 422 est la bonne
#    réponse : une ligne sans provenance vaut moins qu'une erreur visible.
#
# ═══════════════════════════════════════════════════════════════════════════════
# ⚠️ L'ORDRE N'EST PAS INDIFFÉRENT : LE CALLBACK D'ABORD
# ═══════════════════════════════════════════════════════════════════════════════
#
# Un lot Anthropic reste en vol jusqu'à 24 h, et sa metadata est FIGÉE au moment de
# la soumission : le correctif du dispatcher ne l'atteint plus. Un lot soumis avant
# ce réimport peut donc revenir avec `provider: null`.
#
#   · callback réimporté d'abord → il replie sur 'anthropic' et sauve le lot, quelle
#     que soit l'ancienneté de la metadata ;
#   · dispatcher réimporté d'abord → les lots NEUFS sont bons, mais un lot en vol qui
#     revient sur l'ancien callback repart en 422, et le lot entier est perdu.
#
# C'est pour cela que le correctif est posé aux DEUX endroits et non au seul
# dispatcher : l'un couvre l'avenir, l'autre le passé encore en vol.
#
